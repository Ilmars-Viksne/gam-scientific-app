# Scientific Interpretation Guide

This guide provides the scientific foundation for interpreting Generalized Additive Models (GAMs), validation designs, diagnostic outputs, and model artifacts generated by the application.

## 1. Scope and Scientific Purpose

This application estimates predictive classification relationships under the configured data representation and validation design. It does not establish causality, identify physical mechanisms, or provide classical unpenalized coefficient significance tests.

Scientific interpretation requires domain review of:
- the sampling process and data source;
- the prediction target definition;
- the observation unit;
- dependence or clustering among records;
- temporal ordering;
- duplicate and derived variables;
- missing-data mechanisms;
- class prevalence and imbalance;
- target deployment conditions.

## 2. Mathematical Model Formulation

For class $k \in \{1, \dots, K\}$, a main-effects model defines the additive class score $\eta_k(\mathbf{x})$ for predictor vector $\mathbf{x}$ as:

$$
\eta_k(\mathbf{x}) = \beta_{0k} + \sum_{j \in \mathcal{S}} f_{jk}(x_j) + \sum_{l \in \mathcal{L}} \beta_{lk}\widetilde{x}_l + \sum_{c \in \mathcal{C}} \gamma_{ck}(x_c)
$$

where:
- $\beta_{0k}$ is the unconstrained class intercept;
- $\mathcal{S}$, $\mathcal{L}$, and $\mathcal{C}$ represent the sets of smooth, linear, and categorical predictors respectively;
- $f_{jk}(x_j) = \sum_m \theta_{jkm} B_{jm}(x_j)$ is a flexible univariate B-spline term with basis functions $B_{jm}$;
- $\widetilde{x}_l = \frac{x_l - \mu_l}{\sigma_l}$ is a standardized linear predictor;
- $\gamma_{ck}(x_c)$ is a reference-coded categorical main effect.

When pairwise tensor-product interactions are included, the score becomes:

$$
\eta_k(\mathbf{x}) = \beta_{0k} + \sum_{j \in \mathcal{S}} f_{jk}(x_j) + \sum_{l \in \mathcal{L}} \beta_{lk}\widetilde{x}_l + \sum_{c \in \mathcal{C}} \gamma_{ck}(x_c) + \sum_{(r,s) \in \mathcal{I}} f_{rsk}(x_r, x_s)
$$

where $f_{rsk}(x_r, x_s)$ represents a smooth bivariate tensor-product spline interaction surface.

### Softmax Link Function

Predicted probabilities $P(Y=k \mid \mathbf{x})$ are obtained using the softmax inverse link function:

$$
P(Y=k \mid \mathbf{x}) = \frac{\exp(\eta_k(\mathbf{x}))}{\sum_{\ell=1}^K \exp(\eta_{\ell}(\mathbf{x}))}
$$

The model is fitted by minimizing L2-penalized multinomial log loss across training observations.

## 3. Score Identifiability and Transformed Space

In multinomial softmax models, adding a constant vector or scalar $C(\mathbf{x})$ to all class scores $\eta_k(\mathbf{x})$ leaves class probabilities $P(Y=k \mid \mathbf{x})$ invariant:

$$
\frac{\exp(\eta_k + C)}{\sum_{\ell} \exp(\eta_{\ell} + C)} = \frac{\exp(\eta_k) \exp(C)}{\sum_{\ell} \exp(\eta_{\ell}) \exp(C)} = \frac{\exp(\eta_k)}{\sum_{\ell} \exp(\eta_{\ell})}
$$

As a result:
- absolute class scores and raw basis coefficients are not independently identifiable;
- class contrasts relative to a chosen reference class (e.g. $\eta_k - \eta_{\text{ref}}$) express score differences;
- exported reference-class equations describe relative score logits rather than raw marginal probability changes;
- raw transformed coefficients depend on basis choice, spline degree, knot placement, scaling, reference categories, and L2 regularization penalties.

Do not interpret a raw transformed-space coefficient as a direct marginal probability effect.

## 4. Predictor Roles

### Smooth (`smooth`)
- Represents a smooth, nonlinear B-spline term over the observed predictor support.
- Interpret term shapes, curvature, and turning points conditional on other model terms.
- Extrapolation outside the training domain range is unsupported and scientifically invalid.

### Linear (`linear`)
- Represents a linear effect applied to standardized values $\widetilde{x}_j = (x_j - \mu_j)/\sigma_j$.
- Coefficient magnitude reflects change per standard deviation unit, not per raw physical unit.

### Categorical (`categorical`)
- Represents one-hot encoded levels with respect to a designated reference category.
- Coefficients represent predictive contrasts relative to the reference group, conditional on all other model terms.

### Excluded (`exclude`)
- Column is omitted from model fitting. Excluded columns can serve as `row_id`, `group`, `time`, or metadata without causing feature leakage.

Reserved data-role columns (`target`, `row_id`, `group`, `time`) must have `role: exclude` if defined in features to prevent identity-driven or leakage-driven prediction.

## 5. Interaction Terms and Regularization

### Interaction Properties
- Tensor-product interaction terms $f_{rsk}(x_r, x_s)$ capture non-additive joint variation among smooth predictors.
- Interaction terms are fitted hierarchically alongside their constituent main effects.
- Interaction presence indicates predictive joint variation; it does not prove biological, physical, or causal interaction.
- Without functional-ANOVA centering, raw tensor-product interaction surfaces may contain lower-order main-effect components. Inspect overall predictive performance and cross-validation stability.

### Regularization ($C$)
- Inverse regularization parameter $C > 0$ controls model flexibility versus penalty strength.
- Regularization shrinks coefficients toward zero to prevent overfitting, biasing estimated coefficients relative to unpenalized estimators.
- Zero or small coefficients reflect regularization penalties and finite sample sizes, not formal hypothesis tests ($p$-values are not calculated).

## 6. Nested Cross-Validation Design

The application uses nested cross-validation to separate hyperparameter optimization from performance estimation:

```text
Outer Validation Folds:
    Estimate out-of-fold performance on held-out test partitioning.

Inner Validation Folds:
    Optimize hyperparameter combinations (knots, degree, C) using outer-training data only.

Final Model Fitting:
    Fits final deployable models on the complete dataset using optimal outer hyperparameters.
```

- Outer cross-validation performance provides unbiased out-of-fold metric estimates.
- Inner cross-validation scores evaluate hyperparameter selection and must not be reported as final model performance.
- Re-fitting on training data serves model deployment; training performance should never replace outer out-of-fold validation metrics.

## 7. Validation Strategies

Select a validation strategy based on how the model encounters data in deployment.

### Stratified (`stratified`)
- Assumes observations are independent and identically distributed.
- Preserves target class proportions across all outer and inner folds.
- Risk: Cross-fold leakage occurs if repeated measurements, specimen duplicates, or clustered sites exist across folds.

### Group-Aware Stratified (`stratified_group`)
- Enforces that all records sharing an effective validation group remain together in the same fold (in both inner and outer CV).
- Effective validation groups merge configured scientific groups (`data.group`), exact predictor duplicate signatures, and near-duplicate transitive connected components (when `duplicate_group_policy = group`).
- Protects against cross-fold group leakage.

### Time-Aware (`time`)
- Enforces forward temporal ordering: all training observations strictly precede test observations in every fold window.
- Temporal gap (`gap`) creates a buffer between training and test sets to prevent temporal spillover.
- Test window size (`test_size`) controls test horizon evaluation.
- Nonstationary processes may cause performance variation across time windows.

Run `gam-app plan` before execution to verify that class and group counts support the configured outer and inner validation structure.

## 8. Classification Metrics and Fold Variability

### Evaluation Metrics
- **Log Loss** (primary metric): Evaluates full predicted probability distributions and heavily penalizes confident misclassifications. *Lower is better.* (Does not guarantee probability calibration).
- **Accuracy**: Proportion of overall correct class assignments. *Higher is better.* (Can obscure poor performance on minority classes).
- **Balanced Accuracy**: Macro-average of recall across all target classes. *Higher is better.*
- **Macro F1**: Unweighted average of class-specific F1 scores. *Higher is better.*
- **Confusion Matrix**: Summarizes true versus predicted class allocations across out-of-fold predictions.

### Fold Dispersion
Variation across outer folds reflects sample composition, effective group imbalance, temporal drift, or hyperparameter selection sensitivity. Do not report fold standard deviations as formal confidence intervals.

## 9. Predictor and Duplicate Diagnostics

### Correlation Diagnostics
- **Pearson ($r$)**: Measures linear relationship strength.
- **Spearman ($\rho$)**: Measures monotonic rank relationship strength.
- Ranked high-correlation pair tables identify potential collinearity. Collinearity can destabilize individual term coefficients without degrading overall prediction accuracy.

### Derived Variable Diagnostics
- `declared`: Predictor declared as derived in feature metadata.
- `not_declared`: Predictor evaluated and declared as independent.
- `suspected`: Identified potential mathematical relation (affine, log, square, square root). Suspected relations prompt domain review; they do not mandate automatic column removal.
- `not_evaluated`: Metadata was not provided (`metadata_status = not_provided`).

### Duplicate Analysis
- **Exact Duplicates**: Predictor-identical records. May represent legitimate repeated experiments, repeated measurements, or data export duplication.
- **Proper Near-Duplicates**: Records meeting the near-duplicate match threshold (`near_duplicate_threshold`) across canonicalized predictors. Combined transitively into connected components.
- **Conflicting Duplicate Targets**: Predictor-identical records with differing target labels. This indicates unresolved predictor ambiguity—available predictors alone cannot distinguish these outcomes.

### Duplicate Handling Policies (`duplicate_group_policy`)
- `report` (default): Emits diagnostic tables without modifying cross-validation splits.
- `error`: Halts execution prior to split manifest creation if duplicate groups exist.
- `group`: Transitively merges scientific groups and duplicate components into effective validation groups to eliminate cross-fold duplicate leakage.

Duplicate policy `group` addresses partition leakage. It does not alter, delete, or clean source data.

## 10. Transformed Component and Contribution Exports

Model score contributions express additive components to unnormalized class scores $\eta_k$:

$$
\eta_k(\mathbf{x}) = \beta_{0k} + \sum_b c_{bk}(\mathbf{x})
$$

- Contributions operate in logit score space, not probability space.
- Individual score contributions cannot be directly summed to yield probability percentages.
- Softmax transformation is applied after summing all score contributions across all predictors.
- Grouped contributions aggregate individual feature contributions by feature group or interaction family.

## 11. Model Comparison Conventions

When comparing two models (`--left` vs `--right`), metric differences are calculated as:

$$
\Delta = \text{right} - \text{left}
$$

Directional interpretation:
- Positive Accuracy difference favors the **right** model.
- Positive Balanced Accuracy difference favors the **right** model.
- Positive Macro F1 difference favors the **right** model.
- Positive Log Loss difference favors the **left** model because lower log loss is better.

## 12. Model Deployment Limitations

Final fitted models (`model.joblib`) are serialized for batch prediction on schema-compliant datasets:
- Input data must match training predictor names and expected data types.
- Prediction observations should reflect the target deployment population.
- Extrapolation beyond the training predictor domain introduces prediction risk.
- Out-of-fold predicted probabilities are uncalibrated unless post-hoc calibration is explicitly evaluated.
- Only load `.joblib` model files created by a trusted environment.

## 13. Pre-Interpretation Review Checklist

Before drawing scientific conclusions, review the following:

- [ ] Target variable definition aligns with the research question.
- [ ] Observation unit and record independence assumptions are verified.
- [ ] Validation strategy (`stratified`, `stratified_group`, `time`) matches deployment.
- [ ] Grouping variables prevent cross-fold record leakage.
- [ ] Time ordering and gap settings are preserved for temporal data.
- [ ] Feasibility checks (`gam-app plan`) passed without warnings or failures.
- [ ] Split-integrity checks passed.
- [ ] Conflicting duplicate target groups were reviewed by domain experts.
- [ ] High-correlation predictor pairs and suspected derived variables were audited.
- [ ] Outer out-of-fold cross-validation metrics are reported (not training metrics).
- [ ] Confusion matrices and class-specific metrics were examined.
- [ ] Conclusions remain strictly predictive rather than causal or mechanistic.

## 14. Standard Scientific Reporting Template

Use this standard reporting structure when summarizing study results:

> The model was evaluated using [stratified / stratified group / time-aware] nested cross-validation with [X] outer folds, [Y] outer repeats, and [Z] inner hyperparameter selection folds. [For group-aware: Observations sharing an effective validation group were kept in the same partition. / For time-aware: Every training window preceded its corresponding test window, with a temporal gap of G units applied.] Hyperparameters were selected strictly within outer-training data. Predictive performance was evaluated on out-of-fold test predictions using log loss, accuracy, balanced accuracy, macro F1, and confusion matrices. Predictor correlation, derived variable, duplicate group, and split integrity diagnostics were reviewed prior to reporting model performance.
